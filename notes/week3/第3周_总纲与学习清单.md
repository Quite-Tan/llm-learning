# 第 3 周 · 总纲与学习清单

**主题**：Ollama API 深入 + Prompt 工程  
**产物**：`prompts/` 模板库 + `eval_chat.py` 评测脚本 + `notes/第3周_*.md`  
**核心考核**：能不能用同一套代码跑通 5 套不同的 prompt，并用量化的方式说出哪套更好。

---

## 每日清单

### Day 1｜Ollama /api/chat 与 /api/generate 的区别

- 用 curl 直接调一次 Ollama（不经过 Python 库），拿到原始 JSON：

  ```bash
  curl http://127.0.0.1:11434/api/generate -d '{"model":"qwen3:4b","prompt":"你好","stream":false}'
  ```

- 对比 `/api/chat`（messages 数组、role）与 `/api/generate`（prompt 字符串、无角色）的入参和返回字段
- 搞清 `keep_alive`、`num_ctx`、`temperature`、`top_p`、`seed` 各管什么，哪些影响质量、哪些只影响速度

**产出**：`notes/第3周_01_Ollama_API_字段表.md`，一张表列清所有常用参数 + 默认值 + 实测效果

**补漏穿插**：在脚本里用 `os.environ["NO_PROXY"]` 控制代理，验证"必须在 import ollama 之前设置"这句话是真是假（亲手证伪或证实，比背结论强）

---

### Day 2｜system prompt 的威力与边界

- 写 3 版 system prompt：空 / 通用助手 / 严格角色约束（含输出格式要求）
- 同一组 5 道题跑 3 版，记录：是否遵守格式、是否啰嗦、是否幻觉
- 验证一个关键认知：system prompt 不能保证格式稳定，需要结构约束（为 Day 4 铺垫）

**产出**：`prompts/system_default.txt`、`prompts/system_strict.txt`

---

### Day 3｜模板化：把 prompt 从代码里抽出来

- 建立 `prompts/` 目录结构：

  ```
  prompts/
    base_system.txt        # 人设
    format_json.txt        # 要求输出 JSON
    format_table.txt       # 要求输出表格
    doc_inject.txt         # 文档注入片段（接第2周的 DocContext）
    README.md              # 每个模板的用途 + 占位符说明
  ```

- 用 `{placeholder}` 写占位符，Python 侧用 `.format()` 或 f-string 填充
- 改造 `chat.py`：`--prompt <名字>` 命令行参数切换模板，不改代码只换文件

**产出**：`chat.py` v3（支持 prompt 模板切换）

**补漏穿插**：f-string 进阶（`:.2f`、`{expr=}` 调试写法、多行 f-string 与三引号陷阱），记入 `notes/第3周_02_字符串格式化.md`

---

### Day 4｜结构化输出：JSON 稳定性

- 任务：让模型从一段中文文本里抽出「人名、机构、时间、金额」，输出 JSON
- 连续跑 10 次同一输入，统计：合法 JSON 次数 / 键名一致次数 / 值准确次数
- 对比三种方案的稳定性：纯自然语言要求 → 给 JSON Schema 示例 → 用 `format` 参数（Ollama 支持传入 JSON Schema）

**产出**：`prompts/format_json.txt` + `eval_json.py`（单次评测）

---

### Day 5｜评测脚本：把"感觉"变成数字

- 建一个 `eval_cases.jsonl`，每行一条用例：

  ```jsonl
  {"input": "...", "expect_keys": ["..."], "check": "自由文本断言"}
  ```

- 写 `eval_chat.py`：读用例集 → 对每个用例跑 N 次 → 输出表格
- 指标：格式合格率、键齐全率、重复一致性（同题多次输出的相似度）、耗时
- 用这份脚本横向比：`qwen3:1.7b` vs `4b` vs `llama3.2:3b`，同一组 prompt

**产出**：`eval_chat.py` + `results/week3_baseline.csv` + `notes/第3周_03_模型横向评测.md`

---

### Day 6｜Prompt 的反模式与修复

- 故意写烂 prompt：指令矛盾、上下文淹没、负向约束（"不要…"）、过长文档淹没指令
- 观察失败形态，逐一修复，记录"症状 → 病因 → 药方"

**产出**：`notes/第3周_04_Prompt_反模式清单.md`（这张表以后是调 prompt 的第一手查表）

---

### Day 7｜周复盘 + v3 归档

- `chat.py` v3 合并进主分支，打 tag
- 四篇笔记 + 模板库 + 评测脚本全部入库
- 回答三个问题：
  1. 换一套 prompt 要不要改代码？（要改 → 模板化没做彻底）
  2. 换一个小模型要不要改评测脚本？（要改 → 评测与模型耦合了）
  3. 这周写的东西，第 4 周做 RAG 时能复用几成？
- 定第 4 周计划（RAG：文档切分 + 向量检索 + 召回质量评测）
