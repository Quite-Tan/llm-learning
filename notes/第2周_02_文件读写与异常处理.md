## 二、Path：为什么不用 open()

```python
from pathlib import Path

p = Path("sessions") / "default.json"   # 自动处理 / 和 \
p.parent.mkdir(exist_ok=True)            # 目录不存在就建，已存在不报错
p.suffix                                 # .json
p.exists()
p.read_text(encoding="utf-8")            # 一行读完
p.write_text(s, encoding="utf-8")        # 一行写完
```

**对比老写法：**

```python
import os
os.makedirs("sessions", exist_ok=True)
p = os.path.join("sessions", "default.json")
f = open(p, "r", encoding="utf-8")
raw = f.read()
f.close()
```

> **关键区别**：`read_text()` / `write_text()` 内部自动开闭文件。用 `open()` 忘了 `with`，写一半崩掉，JSON 文件就永久损坏。

**规则**：读小文本文件一律 `Path.read_text()`；只有大文件或需逐行处理时，才用 `with open(...) as f`。

## 三、json：中文变成 `\uXXXX` 的原因

```python
json.dump(data, open("t1.json", "w"))                        # 默认 ensure_ascii=True
json.dump(data, open("t2.json", "w"), ensure_ascii=False)    # 中文原样
```

| 文件        | 内容                                     | 可读性   |
| --------- | -------------------------------------- | ----- |
| `t1.json` | `{"name": "\u9ed8\u8ba4\u4f1a\u8bdd"}` | 人类不可读 |
| `t2.json` | `{"name": "默认会话"}`                     | 正常    |

> 功能上两者等价（读回来内容一样），但手动改配置、git diff 看改动时前者完全不可用。

所以 chat.py 里必须这么写：

```python
json.dump(self.data, PARAMS_FILE.open("w", encoding="utf-8"),
          ensure_ascii=False, indent=2)
```

一行里藏了三件事：

| 参数                   | 管什么    | 不写的后果                    |
| -------------------- | ------ | ------------------------ |
| `encoding="utf-8"`   | 文件编码   | Windows 默认 cp936，中文乱码或报错 |
| `ensure_ascii=False` | 中文原样输出 | 变成 `\uXXXX`，可读性归零        |
| `indent=2`           | 格式化缩进  | 全挤一行，git diff 看不出改了哪     |

### json 的类型坑

JSON 只认 `str` / `int` / `float` / `bool` / `None` / `list` / `dict`。以下直接报错：

```python
json.dumps({"f": Path("a.txt")})     # TypeError: Path is not JSON serializable
json.dumps({"tags": {"a", "b"}})     # TypeError: set is not JSON serializable
```

> 存之前必须转成基本类型。`Session.save()` 里的 `datetime.now().strftime(...)` 就是这个道理。

## 四、try/except：分层捕获，别一锅端

### 异常是一棵树

```
BaseException
├── SystemExit              ← sys.exit()
├── KeyboardInterrupt       ← Ctrl+C
├── GeneratorExit
└── Exception               ← 日常几乎都在这
    ├── UnicodeDecodeError / UnicodeEncodeError
    ├── json.JSONDecodeError
    ├── ConnectionError → ConnectionRefusedError
    ├── ValueError / TypeError / KeyError / FileNotFoundError
```

> `UnicodeDecodeError` 是 `Exception` 的子类。这是**包含关系**，不是并列。

### 两者的实质区别

|               | `except UnicodeDecodeError` | `except Exception` |
| ------------- | --------------------------- | ------------------ |
| **范围**        | 只抓解码失败                      | 抓几乎所有情况            |
| **意图**        | "我知道可能编码不对，我有预案"            | "别崩"               |
| **能否针对性处理**   | 能，换 gbk 重试，用户无感知            | 不能，只能打印+降级         |
| **会不会掩盖 bug** | 不会                          | **会**，连变量名打错都能吞    |

最后一条最危险：

```python
try:
    tasks = jason.loads(raw)      # 手滑拼错
except Exception as e:
    print(f"出错了：{e}")          # "name 'jason' is not defined"
```

你会花半小时查文件和编码，其实只是拼写错误。去掉 `except`，Python 三秒标红定位。

### chat.py 的三层结构（背下来）

```python
try:
    stream = ollama.chat(model=self.model, messages=messages, stream=True, ...)
    ...
except ConnectionError as e:                          # 第 1 层：可预期、可恢复
    print("连不上 Ollama 服务")
    print("提示：执行 ollama serve")
    self.history.pop()                                # 有针对性的补救
except Exception as e:                                # 第 3 层：兜底
    print(f"{type(e).__name__}: {e}")
    self.history.pop()                                # 保守补救
```

> 中间缺的第 2 层：`except (json.JSONDecodeError, KeyError)`，应对 Ollama 返回结构异常。这是待办。

### 三条铁律

1. **能写具体异常，绝不写 `Exception`。** 先问："这个错我能针对性处理吗？"
2. **`Exception` 只出现在两处**：程序最外层防闪退；具体 `except` 之后做兜底。绝不出现在业务逻辑内部。
3. **永远不用裸 `except:`** —— 它连 Ctrl+C 和 `sys.exit()` 都吞，程序关不掉。这也是 `input()` 外层要单独捕获 `KeyboardInterrupt` 的原因。

### 顺序不能反

```python
# ✅ 正确：具体在前，宽泛在后
except UnicodeDecodeError: ...
except Exception: ...

# ❌ 永远走不到第二行，Python 3.12+ 报 SyntaxWarning
except Exception: ...
except UnicodeDecodeError: ...
```

> 从上往下匹配，命中第一个就停。宽泛的在上，子类全被截胡。

## 五、chat.py 里其他几个细节

| 写法                         | 原因                        |
| -------------------------- | ------------------------- |
| `MAX_DOC_CHARS = 8000` 硬截断 | 小模型上下文有限，全文硬塞会让它忘掉指令      |
| utf-8 失败回退 gbk             | Windows 下中文文件的常见编码坑       |
| Ctrl+C 也触发保存               | 异常退出不丢数据                  |
| 文档作为独立 system 消息插入         | 和人设分离，`/doc clear` 不用重建历史 |
| 每次重新组装消息而非直传 history       | v2 架构改进：文档载卸不污染历史         |
