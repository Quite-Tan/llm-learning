## 一、为什么函数不够用

纯函数 + 全局变量的写法：

```python
history = []
model = "llama3.2:3b"
temperature = 0.6
doc_text = ""

def send(msg): ...
def clear(): ...
```

**三个致命问题：**

1. **状态散落**：函数之间靠"默契"共享数据，改错一个变量名不报错但行为诡异。
2. **无法多开**：想同时跑 3B 和 4B 两个会话做对比，全局变量只有一份，做不到。
3. **无法复用**：以后接 Streamlit 网页或 Agent 框架，全局状态全部冲突。

> 函数封装动作，类封装「动作 + 它自己的数据」。

```python
c1 = Chat(model="llama3.2:3b")
c2 = Chat(model="qwen3:4b")  # 两份独立状态，互不干扰
```

## 二、self 到底是什么

`self` 不是关键字，只是约定俗成的名字。含义是：**调用我的那个对象自己**。

```python
class Chat:
    def __init__(self, model):
        self.model = model

    def show(self):
        print(self.model)

a = Chat("llama3.2:3b")
b = Chat("qwen3:4b")
a.show()  # self 就是 a
b.show()  # self 就是 b
```

**Python 背后的转换：**

```python
a.show()        # 你写的
Chat.show(a)    # Python 实际执行的
```

**验证：**

```python
>>> c.send          # <bound method MiniChat.send of <...>>
>>> MiniChat.send   # <function MiniChat.send at 0x...>
```

同一个东西两种形态：通过实例访问是 **bound method**（已绑定对象），通过类名访问是**裸 function**。

> **推论**：方法也是对象，可以当参数传递。这是后面做 Agent「工具注册」的基础。

### self 的三个易错点

| 错误写法 | 后果 |
|---|---|
| `def show():` 漏掉 self | `TypeError: takes 0 positional arguments but 1 was given` |
| 方法里写 `model = "xxx"` 不加 self | 只是局部变量，方法结束就消失，状态没存住 |
| `shared_log = []` 写在类体而非 `__init__` | 所有实例共享同一个列表（可变对象的经典坑） |

## 三、实例属性 vs 类属性（核心坑）

```python
class MiniChat:
    shared_log = []           # 类属性：存在类身上，全体共享

    def __init__(self, name):
        self.name = name
        self.logs = []        # 实例属性：存在实例身上，各有一份
```

```python
>>> a = MiniChat("alice"); b = MiniChat("bob")
>>> a.send("hi"); b.send("hello")
>>> id(a.logs) == id(b.logs)          # False ← 各自独立
>>> id(a.shared_log) == id(b.shared_log)  # True ← 同一个对象
```

> **实例属性各有一份，类属性全体共享。** 列表、字典这类可变对象一旦写成类属性，就是 bug 温床。

这也解释了为什么 `history`、`params`、`doc` 必须全部塞进 `__init__`。

## 四、`__init__`：对象的出生登记

`Chat(...)` 被调用的那一瞬间自动执行，职责只有一件：**给新对象装上初始属性**。

```python
class Chat:
    def __init__(self, model=DEFAULT_MODEL):
        self.model = model
        self.params = Params()       # 挂一个参数管理器
        self.doc = DocContext()      # 挂一个文档上下文
        self.history = [{"role": "system", "content": SYSTEM_PROMPT}]
        self.session_name = "default"
```

注意 `self.params = Params()` —— 这里发生了**对象嵌套**，是四个类分工的钥匙。

## 五、为什么是四个类：职责边界

| 类 | 管什么 | 不管什么 | 判定依据 |
|---|---|---|---|
| **Params** | 参数读取、校验、保存、转 Ollama dict | 不知道对话内容 | 一组同构配置项 + 固定操作 → 单独抽类 |
| **Session** | JSON 存盘、读回、列清单 | 无状态，全是 `@staticmethod` | 纯工具操作、无记忆 → 静态方法 |
| **DocContext** | 读文件、编码兜底、截断、造 system 消息 | 不管怎么对话 | 一个明确数据块 + 相关操作 |
| **Chat** | 组装消息、调 API、命令循环 | 不关心怎么存盘、怎么解码 | 协调者/门面，把上面三个拼起来 |

### 判断要不要拆类的三条经验法则

1. **一组函数总是操作同一批变量** → 提成类，变量变属性。
2. **一个类超过 200 行、职责能用"和"字连接**（既管参数又管文件又管对话）→ 拆开。
3. **类里有些方法从不使用 `self.xxx`** → 改 `@staticmethod` 或提到类外。Session 就是这么来的。

> **Chat 是导演，Params/DocContext 是演员，Session 是场记。**

## 六、`@staticmethod` vs 普通方法：一条判别线

问自己：**这个类有没有需要跨调用长期持有的"自己的数据"？**

- **有** → 普通方法，必须能拿到 `self`（Chat、Params）
- **没有**，每次都是"输入→处理→输出"，调完就完事 → `@staticmethod`，连实例都不用建

```python
Session.save(name, model, history, doc)    # 直接类名.方法
# s = Session(); s.save(...)              # 多此一举
```

### 完整判别表

| 自问 | 结论 |
|---|---|
| 方法里用到了 `self.xxx`？ | 普通方法 |
| 多次调用之间要记住东西？ | 普通方法 + 放 `__init__` |
| 只是工具函数，输入输出确定？ | `@staticmethod` 或提到类外当普通函数 |
| 需要用到类本身的属性而非实例？ | `@classmethod` |
