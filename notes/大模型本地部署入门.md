\# 大模型本地部署入门：从环境到第一个模型



\## 一、为什么做本地部署



本地部署大模型不是要完全替代云端模型，而是为了建立一个\*\*可控、可离线、可二次开发\*\*的实验环境。它的价值主要有：



\- \*\*数据更私密\*\*：对话、代码、文档可以不经过第三方服务。

\- \*\*离线可用\*\*：没有网络时也能继续实验。

\- \*\*便于学习\*\*：可以观察模型、量化、推理接口和部署流程。

\- \*\*方便二次开发\*\*：后续可以接 RAG、Agent、知识库和本地 API。



局限也要承认：本地模型能力受硬件限制，超大模型在消费级设备上很难全精度运行；如果只是“拿来就用”，云端模型通常更省事。



\## 二、本地部署的三种主流路线



| 工具 | 适合场景 | 特点 |

| ------ |------ |------ |

| \*\*Ollama\*\* | 个人学习、快速验证 | 上手最简单，一条命令即可拉取和运行模型，提供 OpenAI 兼容 API |

| \*\*vLLM\*\* | 高并发、API 服务 | 吞吐更高，显存利用率更好，适合生产级部署 |

| \*\*llama.cpp\*\* | 低配设备、CPU 推理、极致轻量 | 支持 GGUF 量化，跨平台能力强，适合边缘设备和老硬件 |



个人学习阶段，建议先用 \*\*Ollama\*\* 跑起来；如果想做高并发服务，再考虑 vLLM；如果硬件资源非常有限，或者想研究量化和底层推理，再深入 llama.cpp。



\## 三、硬件门槛：显存决定能跑多大模型



本地部署最关键的不是算力，而是\*\*显存/内存容量\*\*。



一个常用估算公式是：



```text

所需显存 ≈ 模型参数量 × 量化字节数 × 1.2

```



其中 1.2 用于覆盖 KV Cache 和框架开销。



常见量化下的大致需求：



\- \*\*7B / 8B 模型 INT4\*\*：约 4.5–8GB 显存

\- \*\*14B 模型 INT4\*\*：约 8–12GB 显存

\- \*\*32B 模型 INT4\*\*：约 19–24GB 显存

\- \*\*70B 模型 INT4\*\*：通常需要 40GB 以上显存



量化格式选择上，个人使用可以优先 \*\*Q4\_K\_M\*\* 或 \*\*Q5\_K\_M\*\*。Q4\_K\_M 显存占用更低，Q5\_K\_M 质量更好，日常体验通常都比较可用。



\## 四、Windows 环境准备



当前环境已经准备好：



```powershell

conda activate llm

python --version

```



输出应为：



```text

Python 3.10.x

```



后续安装 PyTorch、LangChain、LlamaIndex、vLLM 等库时，都建议在这个 `llm` 环境中完成，避免和系统 Python 混用。



\## 五、用 Ollama 跑第一个模型



Windows 上安装 Ollama，可以去官网下载安装包，安装后服务会默认在后台运行。



验证安装：



```powershell

ollama --version

```



拉取并运行模型：



```powershell

ollama run qwen3:8b

```



如果显存或内存有限，也可以先试更小的模型，例如：



```powershell

ollama run deepseek-r1:7b

```



运行后可以直接在终端对话。退出时可以输入：



```text

/bye

```



Ollama 默认会提供本地 API，例如：



```text

http://localhost:11434

```



后续如果开发 RAG 或 Agent，可以用这个地址作为本地模型后端。



\## 六、模型存储路径



Ollama 模型默认会占用较多磁盘空间。7B 模型大约几 GB，更大模型可能达到几十 GB。



Windows 默认路径通常是：



```text

C:\\Users\\用户名\\.ollama\\models

```



如果系统盘空间紧张，可以把模型目录改到空间更大的磁盘。模型文件较大，建议放在 SSD 上，机械硬盘会明显影响加载和推理体验。



\## 七、后续学习路线



可以按这个顺序推进：



1\. \*\*先跑通 Ollama\*\*：熟悉模型下载、运行、API 调用。

2\. \*\*再学 llama.cpp / GGUF\*\*：理解量化、层卸载、CPU/GPU 混合推理。

3\. \*\*再学 vLLM\*\*：理解 PagedAttention、连续批处理和高并发服务。

4\. \*\*最后接应用层\*\*：做本地 RAG、知识库、Agent 和桌面工具集成。



这篇笔记后续可以继续补充：模型选择记录、显存占用测试、Ollama API 调用示例、vLLM 部署记录，以及本地 RAG 实验。
